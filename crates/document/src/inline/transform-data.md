# Text transformation data

`transform_maps.rs` is generated by `tools/generate_text_transform.py`.
The generator accepts local primary-source files and rejects a hash mismatch.
It writes all mappings and the source-derived exhaustive test records.

- Unicode 17.0.0 [UnicodeData.txt](https://www.unicode.org/Public/17.0.0/ucd/UnicodeData.txt),
  SHA-256 `2e1efc1dcb59c575eedf5ccae60f95229f706ee6d031835247d843c11d96470c`.
  The 226 width mappings invert `<wide>` decompositions and use `<narrow>`
  decompositions forwards. Unrelated compatibility decompositions are excluded.
  Original selected records are in `tests/fixtures/width-decompositions.txt`
  within this crate. Unicode data is licensed under Unicode-3.0; the adjacent
  `Unicode-LICENSE.txt` retains its notice and terms.
- The existing pinned [CSS Text 3](https://www.w3.org/TR/css-text-3/) Appendix G,
  source SHA-256 `17c26f1b41455947f106dac81736944b12da328ee4892c7c5b601f5b65ced55a`.
  All 58 small/full-size kana scalar pairs are reproduced in the match function
  and `tests/fixtures/small-kana.txt`. This includes supplementary-plane and
  half-width mappings. The snapshot, rather than a live revised appendix, is
  the authority for this implementation.

From the repository root:

```sh
python3 tools/generate_text_transform.py /path/to/UnicodeData.txt /path/to/css-text-3.html
```

The Rust implementation applies casing first, width second, kana size third.
Collapsed spaces and expanded tabs retain their existing whitespace semantics;
only preserved original U+0020 spaces become U+3000. The bounded output writer
and paragraph offset mapping remain shared with contextual casing.
